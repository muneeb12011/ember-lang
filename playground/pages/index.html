Reads like you already know it

Ember borrows the parts of Rust, Go and TypeScript that keep programs honest, and leaves out the ceremony. Here is one program, part by part.

import "std/vec.em" as vec;

ModulesEvery name is private to its file unless marked pub. The standard library is written in Ember and ships inside the compiler.

enum Reading { Temp(float), Offline(str) }

fn describe(r: Reading) -> str {
    match r {
        Temp(c) => { return str(c) + " C"; }
        Offline(why) => { return "offline: " + why; }
    }
}

Enums carry data, and match is exhaustiveAdd a variant and forget to handle it here, and the program doesn't compile. The error names the missing variant.

fn keep<T>(xs: vec.Vec<T>, ok: fn(T) -> bool) -> vec.Vec<T> {
    let out = vec.make<T>();
    for i in 0..vec.size(xs) {
        if ok(vec.get(xs, i)) { vec.push(out, vec.get(xs, i)); }
    }
    return out;
}

Generics without the slowdownThe compiler makes one copy of keep for each type it's used with, so generic code runs as fast as code written for one type.

fn main() -> int {
    let limit = 30.0;
    let temps = vec.from_array([24.5, 31.0, 28.2, 33.7]);
    let hot = keep(temps, fn(t: float) -> bool { return t > limit; });
    print(vec.size(hot));
    print(describe(Reading.Temp(vec.get(hot, 0))));
    return 0;
}

Closures, checked typesThe closure gets its own copy of limit. Ints and floats never mix by accident, and every array access is bounds-checked unless the optimizer proves it safe.

Six stages, no borrowed parts

No parser generator, no LLVM: every stage is part of Ember's own source. Each one is a file you can read, and the line counts are real.

  1. Lexer

    Turns text into tokens: numbers in four bases, strings with escapes, comments kept for the formatter.

    lexer.hpp, 278 lines

  2. Parser

    Recursive descent with precedence climbing. Generics, match and lambdas included.

    parser.hpp, 732 lines

  3. Type checker

    Infers generic arguments, checks every match covers every variant, and reports all errors with a caret.

    sema.hpp, 983 lines

  4. IR

    Lowers the checked program to three-address code on virtual registers, one copy per generic instance.

    ir.hpp, 761 lines

  5. Optimizer

    Fifteen passes: propagation, CSE, loop-invariant motion, inlining, tail calls, bounds-check removal.

    opt.hpp, 965 lines

  6. Back ends

    x86-64 with a linear-scan register allocator, a WebAssembly encoder, and a reference interpreter.

    codegen, wasm, interp: 1,428 lines

Every program runs six ways, and they must agree

A compiler bug rarely crashes. It quietly produces a wrong answer. So every test program runs on three completely different executors, with the optimizer off and on, and all six outputs have to match an answer computed independently in Python, byte for byte.

  • 1,000random programs from the differential fuzzer, all six paths agreeing on every one
  • 200runs with a garbage collection forced on every single allocation

What it caught. Three string-handling programs gave different answers with the optimizer on. The cause: the inliner renamed registers inside instructions but not inside runtime-call arguments, so inlined code read the caller's values. To prove the fuzzer would have found it, the bug was put back: it failed 3 of 30 random programs, and the shrinker cut the first one from 51 lines to 16.
